Timed from assumptions you can check, not from a stopwatch: 180 ms per keystroke (an average typist), 600 ms for a page to load, 700 ms to read a results page and find the right link. Change those and the gap moves — the shape does not.

One caveat: measured against Chrome's own address bar for a site already in your history, the gap is far smaller. Chrome autocompletes and quietly preloads the page, so Enter is nearly free. The difference is real if your habit is to search for sites by name — which is most people's habit — and much less if it is not.

What it does

Every keystroke resolves to exactly one intent:

You type Intent What happens
blo site 220+ site catalog matches blocket → goes to blocket.se
hemnet.se address recognised as a URL → goes there directly
teknik search no site matches → runs a Google search
sv ambiguous four sites match → shows a list, navigates nowhere

Being wrong has to be cheap

Auto-navigation is only worth it if a bad guess costs nothing. So it only fires when the top candidate holds at least 75% of the matched score and beats the runner-up by 1.5×; starting the input with a space pauses everything until Enter or a click; and on arrival the destination shows a five-second overlay with the runners-up and a search row, so switching is one click rather than a back-button round trip.

Inside the sites

On catalog sites it also reads the site's own autocomplete and activates the top row: type mac on Foodora and it opens McDonald's; on Elgiganten it opens the MacBook results. It never guesses what "mac" means — the site already knows, and its suggestion list is standard role="listbox" markup, shadow DOM included.

It never runs on banks, government services, health, payment or checkout pages. Eighteen sensitive hosts are excluded from the content script at build time.

Install it

The demo above is not the full extension. The arrival overlay and in-site search auto-pick only work once installed, because a web page cannot draw on or interact with another site.

  1. Download the zip and unzip it. You get a folder called extension.
  2. Open chrome://extensions.
  3. Turn on Developer mode, top right. The load button stays hidden until you do — this is the step people miss.
  4. Click Load unpacked and select the extension folder itself, not a file inside it. Dragging the folder onto the page works too.
  5. Open a new tab with ⌘T and type bl — no clicking first.

Editing the files later? Press the ↻ icon on the extension's card to pick the changes up.

Run it locally

node tools/serve.mjs

Honest numbers

Chrome already prerenders its address-bar predictions, so what this removes is roughly 200–400 ms per navigation. At about 3 seconds to recover from a wrong guess, it has to be right well above 90% of the time to break even — which is exactly why the confidence thresholds, the leading-space pause and the second-chance overlay exist. As a mass-market product the gap this fills exists on purpose. As a personal tool over your own twenty sites, the accuracy is high enough that it pays for itself.

No frameworks, no build step, no tracking. Favicons load from each site's own origin. 60 unit tests.
